# Quality playbook

These are lessons learned from code-quality reviews, so that the engineers get it right the first time. **Every engineer skill reads this file before implementing.** Only the code-quality-engineer edits it, following the rules in its skill: one lesson per pattern, phrased as the target behaviour, at most about 30 active lessons, with mature lessons promoted into the standards and quiet ones retired. Lessons specific to one project live in that project's `docs/QUALITY-PLAYBOOK.md`.

## Lesson format

```markdown
### QP-NNN <Rule, stated as the target behaviour>
- **Applies to:** backend | frontend | devops | all
- **Seen:** N   **Last seen:** YYYY-MM-DD
- **Why:** <the cost of getting it wrong>
- **Instead of:** <short snippet or description>
- **Do:** <short snippet or description>
```
